# برنامه‌ی اجرایی Petal

## هدف و محدوده

این برنامه نقشه‌ی راه هدفِ تأییدشده‌ی Petal را مشخص می‌کند: مدیریت پروژه و تخته‌ی کانبان، ورود آزمایشی، API با FastAPI، ذخیره‌سازی پایدار برای هر کاربر و دستیار AI از طریق OpenRouter. این سند به‌تنهایی مجوز اجرای هم‌زمان همه‌ی مراحل نیست؛ هر مرحله باید پس از تکمیل معیارهای پذیرش خودش بسته شود.

قابلیت‌های تیمی، نقش‌ها و مجوزهای پیچیده، پرداخت، چندسازمانی و هر قابلیت خارج از این فهرست جزو محدوده نیستند.

## فرض‌ها و تصمیم‌های پیشنهادی

- فرانت‌اند موجود در `frontend/` مبناست؛ پیش از بازنویسی، قابلیت‌ها و آزمون‌های موجود را بررسی و حفظ کنید.
- بک‌اند پیشنهادی FastAPI و پایگاه‌داده‌ی محلی پیشنهادی SQLite است. طرح دقیق داده و قرارداد API پیش از پیاده‌سازی مرحله‌ی پایگاه‌داده باید برای تأیید کاربر ارائه شود.
- ورود با نام کاربری `user` و گذرواژه‌ی `password` فقط برای نمونه و توسعه است، نه احراز هویت مناسب محیط تولید. بررسی ورود باید سمت سرور انجام شود. تصمیم کاربر برای حفظ ورود: کوکی امضاشده‌ی `HttpOnly` با کلید امضا از متغیر محیطی؛ تنظیمات و رفتار آن در مرحله‌ی ورود مستند و آزموده شوند.
- کلید OpenRouter و کلید امضای نشست، در صورت نیاز، فقط از متغیرهای محیطی سمت سرور خوانده شوند؛ هیچ کلیدی در کد، مخزن یا bundle فرانت‌اند قرار نگیرد.
- آزمون‌های خودکار AI باید از پاسخ ساختگی استفاده کنند. فراخوانی زنده‌ی OpenRouter برای `2+2` فقط آزمون دستی اختیاری با کلید و اجازه‌ی کاربر است.
- مستندات طراحی و تصمیم‌ها در `docs/` نگهداری شوند؛ README حداقلی بماند.

- فهرست پروژه‌ها و تخته از API خوانده می‌شوند؛ ساخت پروژه، ویرایش ستون، افزودن/حذف/انتقال/مرتب‌سازی کارت‌ها و افزودن ستون از طریق `PUT` تخته ذخیره می‌شوند.
- کاربر واردکردن یک‌باره‌ی شناسه و نام پروژه‌های قدیمی را تأیید کرد. کلید قدیمی `petal-projects` به‌عنوان پشتیبان حفظ می‌شود و API واردسازی در صورت تکرار idempotent است. کارت‌ها و ستون‌های تغییر‌یافته‌ی نسخه‌ی قبلی در `localStorage` ذخیره نمی‌شدند و قابل بازیابی نیستند.
- حالت‌های بارگذاری، خطای API، نشست منقضی‌شده و ذخیره‌ی ناموفق نمایش داده می‌شوند؛ تغییر نام محلی تا موفقیت API به‌عنوان ذخیره‌شده نشان داده نمی‌شود.
- `npm test`: موفق، ۱۱ آزمون؛ `npm run test:e2e`: موفق، ۱۶ آزمون، شامل واردسازی قدیمی و ماندگاری پس از reload.
- `python -m pytest tests`: موفق، ۲۴ آزمون؛ API واردسازی قدیمی نیز در برابر درخواست تکراری آزموده شد.
- `npm run lint`, `npx tsc --noEmit` و `npm run build`: موفق.
- آزمون‌های E2E از پایگاه‌داده‌ی موقت و پورت‌های مستقل استفاده می‌کنند تا داده‌ی محلی توسعه تغییر نکند.
